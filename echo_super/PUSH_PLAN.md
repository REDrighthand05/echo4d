# 全面推送预备方案（2026-10-31 旁聊预备，未启动）

## 推送的是什么

把超级函数从「旁路军营」推成软件本体的**唯一调度**：
软件不再写死流水线顺序，只喊一声 `super_call(视频, target=scene)`，
路线由它自己排。**推的是调度权，不是放行权**——待审的23项技术
不随推送批量进场，照旧逐个验、验过才注册。

## 三步走（不一刀切）

1. **影子模式**：超级函数只出方案、不干活，和现有写死流水线对照。
   两边路线一致、产物一致，才进下一步。对不上就停在影子，不硬推。
2. **半接管**：新任务走超级函数，老路保留作回退；某个内核坏了
   它自己绕行，绕不过去自动退回老路出场景。
3. **全接管**：老路退役成一个普通内核（仍可被调用），调度权归一。

前置动作：主线8个阶段逐个挂卡注册（映射已在 README 里，一行一个）；
已入列的3个真内核直接复用。

## 统一测试（推送的闸门，也是一键验货机）

一键全跑，四层，任一层红灯就不许往前推：

| 层 | 测什么 | 现有件 |
|---|---|---|
| 零件 | 每个内核单测（吃吐对不对） | real_kernels 3 项 + 各工单自测 |
| 路线 | 找路/跳步/选优/失败绕行 | echo_super 7 项 |
| 冻结 | 两个保命功能锁死不许改：点云固化、深度画面 | voxel_frozen 等 |
| 整机 | 月亮视频 + 房间视频各跑一遍，出得来场景才算过 | pipeline 冒烟（最慢，单独开关） |

入口：`run_all_tests.py`（已建，基线见本文末）。

## 加速开发的形状

- **生产并行**：DS 工单可以多张同时写（零件之间互不知情，天生可并行）。
- **审核串行**：我逐个验，这是规矩，也是唯一不许加速的一步。
- **验货自动化**：统一测试把「验」从人肉变成一键——验得快，才敢产得快。
  所以加速的真正杠杆不是多派活，是统一测试先行。
- **盘点并行**：第二批册子（学习链/传感链）可与推送同时编，不占主线。

## 不许动的东西

- 冻结功能（点云固化、深度画面）在推送期间行为不变。
- 发版门不变：核心形状过关 + 真前端做好，才打包 exe（用户已定）。
- 证据标签不变：估计类永远标估计，不冒充实测。
