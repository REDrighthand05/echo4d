# ECHO / Echo4D — 产品初心与防漂移准则

> 长程研发必须定期回看：Issue #1 是用户愿景的历史来源；Issue #4 是有限模块棋盘；Issue #15、#47 是研发证据；Issue #74 是当前实景视觉硬门槛。本文补充执行规则，不覆盖这些原始档案，不宣称已实现的能力。

## 为什么开发

最终目的是让生活中有限且有出处的传感器记录，在未来尽可能被还原为**可以自由进入、从多个角度观察、沿时间回放**的过去空间。ECHO 是可信的空间记忆系统，不是单纯的 AI 生图、漂亮的 4D 视频、Mesh 数量比赛或多项目堆叠。用户接受低模；不接受碎片化几何被吹成「已经还原现实」。

长期愿景包括：轻量可穿戴采集、按需增加探测强度、眼镜显示、离线重建、多算法合作、动态主体/骨架、历史空间回访。设备功能与人体身份处理是**远期目标**，不是当前已交付功能。后期可靠算法验证后，才能研究将它们增量化、局部化、量化后迁到低功耗实时模式。

## 历史系统的双视角：先保存真实，再逐步重建

- **第一人称真实时间轴**：眼镜沿视觉朝向持续记录原始清晰画面及时间；将来直接播放当时真实记录的画面，不以AI补帧或3D渲染替代录像原片。即使没有可用三维算法，历史第一人称回放仍应独立可用。
- **自由第三人称时间轴**：在真实记录及跨时间积累的资料中恢复可辨认的时变场景；用户可以暂停时间、自由观察，甚至查看自己当年的动作（仅在该动作有足够记录依据时）。已观测、实测、推算、AI修饰及未知不相互冒充。
- **互补采集**：IMU帮助恢复眼镜运动，实测深度/扫描提供可见几何；非电离的近场或遮挡后结构探测是未来可选研究支路，只有实际传感数据经校准后才能纳入 Mesh，不声称现有眼镜可以穿墙精确成像。可视化参考《Detroit: Become Human》的空间重建网格，不等于相关游戏能力已实现。
- **逐步完善历史**：同一物体的形状知识可以由不同时刻的资料补充，但其每个历史时刻的位置、状态与事件仍需单独约束。低模优先恢复真实空间，高模AI可以有界完善表现，不覆盖真实几何层。
- 记录管线和技术边界见 [历史传感流与时空回访](HISTORY_CAPTURE_PIPELINE.md)。浏览器第一人称短时原型为 dist/history.html；它不是可穿戴量产设备。

## 永远要守住的事实边界

1. 先保留高清源 RGB、时间、内参/位姿/尺度出处、SHA、数据许可；算法降采样图或 80×60 预览不得伪装成高清原图。
2. 观测、估计、生成、未知四层分开存。推测可供交互，但不得覆盖真实 Mesh 或伪称历史确证。
3. 多路线：15类输入×42条v1组合（#4 / 目录版本）逐路线构建、实跑、独立验收。共享模块只开发一次；任何一个技术路线不得霸占全项目。
4. 真实有结构：至少能认出原图存在的墙、桌、地面、物件及空间相对关系。可保留真实空洞，但不得用碎片伪称「低模通过」。
5. 当前 P0 #74 要有 >=3 对完整来源原图/相同 Mesh 同相机位渲染、>=2 个自由第三人称视角、12帧冻结留出报告和独立人工审阅。截图须可追溯原始文件、同一 Mesh SHA、相机位姿和重建命令。上传截图只等于准备审阅，**不自动判 PASS**。
6. 桌面实验 desk V2 的冻结深度门槛为 15cm，原 16.7779cm FAIL，重复约 16.5386cm 仍 FAIL；不得为美观更新门槛。深度留出不代表独立实物几何真值。
7. 不因代码绿灯、PR合并、注册相机、三角面数、AI自己的评分，就宣称已重建出那个空间。
8. 私人生活影像、位置、人物身体数据采用本地优先、最小保留、授权采集、可删除、可审计；公开仓库只用合法可分享的场景样本。

## 每个模块、分支、PR 必须回答

- 这一步对「未来从记录重回真实现场」有什么可检验的增益？
- 它服务哪些输入格与路径组合？是否与现有 M00–M14 共享合同重复？
- 真实输入是什么？原图是否经过降采样？生成/估计/实测是否混淆？
- 与之前冻结结果相比，**哪里好、哪里坏、哪里没有证据**？有哪些失败反例？
- 对一般用户能否看懂/操作、对普通机器能否安装？没有 UI 的研究模块如何把结果导出到共用检查台？
- 提交验收证据具体落在哪个文件、报告、图像、SHA 和 CI run？

**反漂移触发器**：当工作只增加算法名、工作流数量、漂亮演示、碎片三角面或自我打分，却没有让一张清晰照片对应的真实场景更可辨认、更可自由检查时，在 PR 标为「产品价值尚未证明」，不对外宣传验收成功。可以继续探索该路线，但必须诚实保留失败，并让其他路线保持可选。

## 开始与收尾

每轮首先读取此文件 + Issue #1、#4、#74（含最新正文与评论），再读取目标子任务的新状态。新 UI 功能对所有分支使用同一份公共静态前端，算法分支只需遵守场景数据合同，不得复制分叉出多套互不兼容的产品界面。
