# ECHO 路径策略：有限模块棋盘 v1

**用户于 2026-10-27 确定的开发原则：给定输入条件，组合可替换技术模块，分别构建、分别验证；共享功能只开发一次。** 本文是项目开发策略约束，不是某条算法已经成功的证明。关联 [#4](https://github.com/REDrighthand05/echo4d/issues/4)、[#15](https://github.com/REDrighthand05/echo4d/issues/15)、[#47](https://github.com/REDrighthand05/echo4d/issues/47)、[#74](https://github.com/REDrighthand05/echo4d/issues/74)。

## 固定的是下棋规则，算法与路线保留替换空间

“国际象棋/有限元国际象棋”在这里是**有限模块、有限组合、逐格实验**的类比，不是引入有限元物理求解器，也不保证搜索一定找到成功方案。

- 棋盘格由“输入条件 × 技术模块组合 × 版本/参数 × 数据集 × 验收协议”共同确定。任意输入都登记；缺条件、退化、成本超预算也是明确结果。
- 不把 RGB-only、IMU、已有Mesh或某个模型设成全项目唯一通道。不因最熟悉一条路线而删掉其他候选。
- 所有列出的组合进入长期开发/验证待办。先实现被多条路线复用的模块；资源有限时分批执行，不要求同时开42条实现分支、不复制42份系统。
- 一条组合FAIL只影响它的已测条件，不能证明所有组合失败。变更组件、输入或参数要创建新实验身份，保留原FAIL。
- “防止死胡同”来自可替换接口、完整候选与失败证据；不是通过多路线数量保证成功。未经实跑，成功概率标为**未估计**，不以路线数编造百分比。
- 用户已授权此模块化方向的文档与可审查构建。既定范围的可逆模块开发不逐次要求重选唯一主/备路线；新增付费算力、外部发布及改变验收门槛仍按实际授权处理。

## v1 有限全集：为什么是42种

先固定**静态场景重建的路线家族**，并非声称穷尽世界上一切算法或未来传感器。

| 轴 | 取值 | 含义及主要输入 |
|---|---|---|
| 位姿 P | P0 / P1 / P2 | 已有外部位姿 / 视觉估计 / 视觉惯性估计；分别核对已有位姿、图像重叠、视频+IMU+标定同步 |
| 几何来源 G | S / V / N 的任一非空子集 | S=实测深度或经标定投影的扫描；V=传统多视角几何；N=模型预测；共 S、V、N、SV、SN、VN、SVN 七种 |
| 已有场景 K | K0 / K1 | 不使用旧Mesh / 经来源、时间、世界系审核后复用旧Mesh |

所以完整笛卡尔积是 **3 × (2³−1) × 2 = 42**。仅三种单几何来源有18条，混合来源另有24条；不任意截断成20条以漏掉组合。混合不等于平均深度：各来源分别保存、处理遮挡与冲突后再融合。

## 输入条件的全部排列组合

v1 沿用 #75 提出的15个输入ID（只共享名称，不依赖该PR的运行时代码）。按JSON目录顺序，第 i 项对应掩码第 i 位：1表示声明提供，0表示未提供。**2¹⁵ = 32,768种存在/缺失组合 × 42条路线 = 1,376,256个格子**，包含缺输入的格子，不只输出“可行”项。

```bash
# 42条完整路线；每行一个JSON对象
python tools/enumerate_strategy_chessboard.py

# 0=全部缺失；32767=15项均声明提供；两者各输出全部42条
python tools/enumerate_strategy_chessboard.py --input-mask 0
python tools/enumerate_strategy_chessboard.py --input-mask 32767

# 全量流式枚举；这是规划目录，没有启动1376256次重建
python tools/enumerate_strategy_chessboard.py --all-inputs > chessboard-all-inputs.jsonl

# 检查本文42条与冻结目录一致
python tools/enumerate_strategy_chessboard.py --check-docs
```

全量文件由命令可重复生成，不把百万行重复元数据塞进Git。某格为 `declaration_candidate` 仅表示最低声明输入满足；不验证照片、文件、标定、配准或实现。视频帧数、视差、单张/多张、质量、同步误差、单位、预算均须运行时核对。零输入、只有音频/GPS、单张照片无足够几何约束等照样登记缺项/退化，不能虚构Mesh。

`semantic_masks`、`independent_truth`、`audio`、`gps`等输入也在15位全集内；未被某条必需组使用，不意味着其消费模块已实现。独立真值只能给验收，不能因为“全信息输入”就进入建模。单张图的预测层不能升级为真实场景完成。

## 技术后端与其他分支怎样扩展

42条是模块角色组合，不是42个写死的外部软件名单。COLMAP等后端、原生TSDF/其他融合器、具体预测模型，在相应模块槽位下注册供应者与确切源码/权重版本、许可证、输入输出和预算；换后端属于不同实验。**当前枚举器没有枚举后端/权重/参数的无限空间，也没有提供构建执行器或重建插件加载器。**

一个已冻结实验另附有限 `provider_assignments`（每个模块一个后端及revision）、有限参数表、数据SHA与协议SHA；对这些**显式登记的有限选项**做乘积，才是该轮的全部具体实验。不允许把“任意技术组合”理解为跳过接口兼容性：单位不一致、坐标未对齐、来源冲突应在构建前拒绝并保存原因。新增位姿角色、LiDAR直接几何而非相机投影、纯资产查看、动态人物/4D、外观GS层或实时约束，需扩展版本/专门分支，不能悄悄改v1含义或假称已覆盖。

#75 的十条高层CLI路线暂不改变ID和语义：测深已知位姿对应 P0-S-K0，视觉+测深对应 P1-S-K0，丰富视频+IMU+测深+Mesh对应 P2-S-K1；其他高层路线可能映射多个格子或仅为定位/资产查看任务。**十条CLI目录和本42条研发组合不是一一对应，CLI目前不会自动执行这些新组合。** 后续统一显示应消费本冻结目录、保留原profile兼容，而不是维护两套自称完整的运行态枚举。

## 每条分支都构建，共享模块只实现一次

[模块文档](STRATEGY_MODULES.md)规定输入输出和目录责任；[验证文档](STRATEGY_VALIDATION.md)规定逐格证据和接收条件。路线状态沿 `planned → module_ready → buildable → executed → reviewed` 记录，后面另记PASS/FAIL/BLOCKED/INCONCLUSIVE；进到某一阶段不自动意味着质量达标。

实现模块 → 冻结接口 → 单独审查接收 → 在依赖它的每条路线重新组合与验证。只有同一输入、同一模块版本/参数、同一上游输出SHA才可复用缓存；下游的真实集成与路线验收不能省略。所有分支进入待办，但优先交付一组高信息真实闭环和共享模块；同时可在互不冲突的模块上开发其他路线。某条路线不因“已有替代路线”自动取消；暂停时写原因和恢复条件。

**现状边界**：已有外部位姿+RGB-D、视觉位姿+传感器尺度/深度的旧链有TUM E3实跑；完整VIO、多源几何、旧Mesh联合增量融合仍缺。原desk V2 16.7779cm/15cm **FAIL不变**。本次交付是策略与枚举，不声称42条已构建、已重建或已验收。
