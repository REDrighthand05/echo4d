# ECHO 前端体系：共享产品壳 + 独立重建模块

## 现有资产与近期交付

- 当前 dist/index.html 是无第三方运行时依赖的 WebGL/Canvas 查看器：导入 ECHO JSON、网格/轨迹/时间轴、传感器视角与自由视角、合成实验。保留这个成熟度较高的资产，不以新模板重写整个核心。
- dist/quality.html 是新的「实景质量工作台」：本地加载 >=3 对原图和同位姿 Mesh 证据图、>=2 个自由相机视图，计算各文件 SHA-256，导出可审阅的检查清单 JSON。此页**不替代实际三维渲染**，不验证截图是否真的出自同一 Mesh，也**不能自行签发 #74 PASS**。
- 统一色板、导航、离线优先、未知/推测/观测区分。必须在手机与桌面上可读、键盘可操作。
- 浏览器打开：在仓库根目录运行 python -m http.server 8080 --bind 127.0.0.1 --directory dist，然后访问 /index.html 或 /quality.html。静态前端不执行后端重建。

## 技术选择与参考

借鉴 Rerun (https://github.com/rerun-io/rerun) 的时间与多视图诊断思路、Pascal Editor (https://github.com/pascalorg/editor) 的编辑器/查看器分离、Triplex (https://github.com/pmndrs/triplex) 的可视控件理念。本轮只借鉴交互模式，**没有复制第三方源码、素材或嵌入它们的运行依赖**；以后集成前单独审查许可证、复杂度和浏览器资源代价。

共用产品接口仍是 docs/FORMAT.md 中约定的 ECHO scene / 记录格式；算法 M00–M12 通过经过验证的适配器供给 M13 前端，不应按路线复制前端。后续真实可用性优先级：
1. 原始清晰 RGB 与同一 Mesh 对齐的相机视角、自由视角联动；
2. 场景来源/观测区域/推测与空洞的明确标注、时间与来源；
3. 可冻结报告、可保存的人工判读，能浏览失败案例；
4. 普通用户的一步导入与明确失败反馈；
5. 最后才是换渲染引擎、复杂皮肤/3D 特效、设备端 HUD。

## 各分支共用安装规范

主干 dist/ 是唯一可复用的前端源。不要对42条重建路线分别安装 React/Vite/three 等技术栈；那会造成不必要的分支差异和维护成本。新分支基于 main 自动继承前端。既有研究分支可以在自己的工作区执行：

    python tools/install_frontend.py --source origin/main

脚本只安装带显式清单的共享前端质量工作台文件，不覆盖正在独立开发的算法、已有入口页或 PR 修改的 dist 文件；如果目标已经有不同内容，默认拒绝，必须人工确认取舍。可以加 --check 校验当前工作区的模板是否齐全。

GitHub Actions 的分支预览/安装不得直接修改冻结实验 head、覆盖研究分支的同名文件、自动合并带过期证据的 PR；应将共享 frontend 作为独立构建资产和可审阅更新，而非把任何 UI commit 自动标为重建质量提高。

## 验收

- 静态资源可由本地 HTTP 直接访问，浏览器不需要 CDN 和联网；
- 浏览器中源图片只保存在本地内存，绝不自动上传；
- 真实采集图片与 Mesh 截图必须单独上传，质量页在缺材料时继续显示未验收；
- 文件名、尺寸、SHA、来源说明和工作笔记可导出机器清单；
- 技术 UI 进度和场景重建质量分别写结果。
