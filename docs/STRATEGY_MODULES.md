## 共同接口约束

现行 [FORMAT.md](FORMAT.md) 的米制camera-Z、右手系、列优先camera-to-world保持；本设计没有放宽 `echo-dataset-1` 也不修改现有读取器。新源先经适配器明确转换，才进入现有核心。

每个拟议模块产出都附：模块ID、provider及源码/权重revision、参数哈希、输入/输出SHA、源帧ID与时间、内参/畸变、外参方向、单位/尺度来源、有效mask、观测类别、失败原因、耗时与峰值RAM/VRAM。矩阵目录本身不能签认这些字段真实。

- **量纲未知**：可保留相对重建作研究输出；在物理尺度没通过独立依据核查前，不能送入只接受米制的TSDF或标记米制。已有位姿不自动证明有米制，预测“metric”也不等于测量。
- **多源冲突**：S/V/N分别存储。先在共同坐标/时钟中诊断，再选择/融合；未观测区域保留未知，不直接平均、补洞或把预测覆盖成实测。
- **旧Mesh**：登记出处、年代、坐标和对齐依据。旧模型的未变化假设必须可审核；K0消融不能在缓存或参数中暗用旧Mesh。
- **独立真值**：由M14消费，不进入M03–M11优化。它在输入目录出现不等于允许训练读取。
- **外部技术替换**：冻结provider版本、权重许可证与实际性能。角色相同不代表格式兼容，先做适配器合同，再做真实集成。这里没有宣布选用或安装新的外部依赖。

## 为什么能够并行开发，以及合并顺序

可以按模块分工：M05做VIO适配、M07做多视角几何、M08做预测几何、M10做旧Mesh对齐、M14准备隔离验收；这些任务共享合同和夹具，各自保留Draft PR。示例分工不是指派某个自然人，也不代表已启动并行代理。

| 阶段 | 可并行内容 | 汇合条件 |
|---|---|---|
| 接口冻结 | 输入清单、坐标/时间/量纲、证据清单、验收协议 | 合同版本明确；模块路径责任和依赖登记 |
| 模块开发 | 不同模块的适配器、反例、合法公开夹具 | 各自可调用；代码与依赖审查完成 |
| 共享模块接收 | 按依赖拓扑逐个接收已验证功能 | 固定head、实际tested checkout、应跑CI与回滚点 |
| 路线组合 | 重用同一模块，构建不同P/G/K实验 | 所需provider已实现；接口/单位/坐标兼容 |
| 独立验证 | 不同冻结场景/输入格子的实跑和审阅 | 每格独立报告；不复制其他格PASS |

同一公共文件由一项PR负责主修改，其他PR依赖它或扩展适配器，避免不同路线各写一套COLMAP导入、评分器或NPZ格式。合并功能模块不等于所有消费路线成功；路线A失败不阻止已通过合同审查的共享模块供B使用。

每个模块PR标注：`module_ids / affected_route_ids / base+head SHA / dependencies / interface_version / actual_tested_checkout / tests / real_run / unresolved / rollback_sha`。路线实验再记录具体模块版本组合。未满足集成门槛保留Draft，允许交付明确失败；不把所有研究分支不加审查混入main。
