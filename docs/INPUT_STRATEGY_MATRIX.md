# ECHO：输入信息 × 重建策略选择器（开发 Feature，草案）

关联 [Issue #4：多策略与实时化技术选型](https://github.com/REDrighthand05/echo4d/issues/4)、[Issue #15：完整重建](https://github.com/REDrighthand05/echo4d/issues/15)、[Issue #74：可辨认场景实景验收](https://github.com/REDrighthand05/echo4d/issues/74)。

**项目策略属于用户。** Agent/程序负责呈现证据、可用模块、投入成本与未知，不得擅自把“RGB-only先造粗模型”或任何别的路线作为所有场景的唯一起点。本功能第一版是**CLI + JSON + Markdown 表格**，可让后续网页或 Agent 消费稳定输出；它**并不调用三维重建、IMU融合或外部网络，也没有浏览器路线选择UI**。

## 使用方式

```bash
# 列出完整候选清单和每种输入的真实核验要求
echo4d strategy
echo4d strategy --format json

# 声明本次可用输入；不需要将私人视频、IMU字节上传到外部
echo4d strategy --profile examples/strategy/rich-video-imu-mesh.json
echo4d strategy --profile examples/strategy/rich-video-imu-mesh.json --format json

# 用较少信息对照：算法只比较输入条件，不“预测”没有跑过的准确率
echo4d strategy --profile examples/strategy/video-and-calibration.json
```

方案文件结构（所有输入键可见于 `echo4d strategy --format json` 的 `input_catalog`）：

```json
{
  "version": "echo-strategy-profile-1",
  "goal": "reconstruct_scene",
  "inputs": {
    "rgb_video": {"status": "present", "notes": "来源与原分辨率待核"},
    "imu": {"status": "present", "notes": "需核对时钟、偏置、外参"},
    "existing_mesh": {"status": "present", "notes": "来源与世界坐标尚未核实"},
    "camera_calibration": {"status": "present"},
    "time_sync": {"status": "present"}
  },
  "choice": {
    "primary": "video_imu_mesh_no_depth",
    "backup": "rgb_video_sfm_only"
  }
}
```

- `absent`：没有此输入；未列出的输入也被当作**未知/未提供**，显示为缺少而非擅自推断。
- `present`：用户声明拥有资料，**不表示**资料可信或已经配准。
- `checked`：用户声明检查过，必须附 `evidence` 指针；**这个程序没有验证该指针、哈希、坐标或许可**。真实运行的结果仍需项目证据流程确认。
- `goal` 支持 `reconstruct_scene`、`investigate_limits`、`inspect_existing_assets`，用来记下研究目的，暂不自动调整路线排名。
- `choice.primary` 和 `choice.backup` 是用户自己选择的路线 ID，**完全可留空**。即使用户刻意选择输入尚不齐的路线，软件也会显示缺项而不暗改选择。
- 每条路线的输入组之间是 AND，组内是 OR（例如视频或照片）。`candidate` **只表示声明的最低输入存在**，不表示已经成功、通过合法性审查、技术集成可用或有独立真值；所有质量检查都列在 `checks_not_performed`。

## 要研究的不是一条“难度等级”，而是一组可互相消融的输入

| 输入情形 | 先检查的组合路径 | 已有ECHO资产 / 尚缺的集成 | 主要不能推断的事 |
|---|---|---|---|
| 视频 + IMU + 实测深度 + 已有Mesh + 标定/同步 | Mesh配准 + VIO/SLAM + 实测融合 | TSDF已有真实试验；**IMU与现成Mesh联合对齐仍未集成** | 旧模型不一定是拍摄时状态，没扫过的区域无证据 |
| 视频 + IMU + 已有Mesh，无稠密深度 | VIO + 图像到Mesh注册/变更检测 | Mesh格式/相机定位有局部模块；联合程序 **E0** | 新出现的物体/遮挡面的真实几何 |
| 视频 + 现成Mesh，无IMU | 图像到模型配准，利用模型先验 | 现有SfM/严格几何IO是子模块；**配准还没E3** | 自动变更检测、时变资产、尺度/位姿一致性 |
| 同步RGB-D + 已知真实相机轨迹/标定 | 已有 `echo4d` 直接TSDF | **E3：TUM数据跑过**；加入旧Mesh需要另开发 | 没采到的表面，不等于完整房间 |
| 同步RGB-D视频 + 标定，位姿由软件算 | COLMAP + 传感器锚点尺度 + TSDF | **E3：ECHO TUM实验**；desk冻结深度RMSE仍FAIL | 不能把稀疏定位或同传感器误差当场景可辨认 |
| 视频 + IMU + 标定，无深度/Mesh | VIO/VI-SLAM + 密集几何另求 | **E0：ECHO未接入IMU求解器** | IMU不是稠密深度；尺度/动态退化需检验 |
| 视频 + 标定，无深度、Mesh、IMU | RGB SfM；如需完整几何再接MVS/预测深度 | **E3仅是稀疏相机路线**；密集真实Mesh未证 | 真实米制尺度、遮挡与细节 |
| 多视角照片，没有传感器 | SfM+MVS/深度预测候选 | 有图片输入基础，但完整场景 **待实跑** | 摄影缺失的表面、低视差深度 |
| 只有现成Mesh | 审核模型来源和打开资产 | 现有有限格式读取/场景检查 | 不能证明现成模型就是现在/过去的现场 |

这张表描述的是**可实现性和信息缺口**，不是给某条路径打“容易”“更优”的分数。比如已知相机轨迹+实测深度是可运行的低未知量基线；现成Mesh如果没有来源、尺度、时间和坐标配准，仍可能是难题。用户可以任意挑主路径和备用路径。

## 从高信息输入逐步抽离：公平实验设计

1. **R0 完整证据基线**：真实清晰RGB视频/照片 + 有效内外参/时钟 + IMU + 已有Mesh/点云 + 实测深度（如有）。先对已有Mesh做来源审计与对齐，尽量复用，而非从零建所有东西。若某个联合组件还未集成，明确计为未完成，不借其他案例伪报整链成功。
2. **R1 消融已有Mesh**：保留完全相同视频、内参、时间和IMU/测深，观察是否能独立得到相似结构；已知旧Mesh不得以“真值”泄漏给去Mesh组。
3. **R2 消融IMU**：其余输入和预算固定，比较轨迹漂移与重建成果；若前一轮已缺Mesh，记录路径身份，别比较不同场景。
4. **R3 消融深度/独立米制锚点**：评估从可观测尺度转为相对尺度或预测深度后，误差、可见结构与未知范围如何变；不可事后用GT调整结果宣称具有米制。
5. **R4 稀疏化照片/缩短或破坏视频覆盖**：检查弱纹理、近纯旋转、遮挡、重复纹理与不同相机标定；如只剩单张照片，明确哪些三维是生成性假设。

这些是**实验变量方向**，不是严格全序，也不是必须以这个固定次序移除；因为来源相互独立、互补，真实难度还受标定、同步、原Mesh质量影响。机器输出 `input_ablation` **只列输入要求因此失效的路线**，不捏造精度、速度、资源的变化。实际消融必须使用受控数据和新的冻结协议、源 SHA 与运行命令。

## 所有路线共享的不可绕过验收

- **原图不能拿预览冒充。** 记录原始RGB分辨率、进入算法的RGB/深度分辨率、抽帧/降采样策略与源SHA。已知desk先例：640×480 原图，算法160×120，预览80×60；现有结果不能证明原图清晰度。
- **空间必须辨认得出来。** 至少三张原照片分别对应真实Mesh相机视角，另外两个自由第三人称视角；桌/墙/物体相对位置、漂浮碎片、孔洞和未知区域由人审核。不能用独立生成的示意图/库存Mesh蒙混。
- **误差与覆盖同时核对。** 完整未参与建模的数据、逐帧失败/尾部误差、不参与拟合的独立参考；允许FAIL且必须保留。desk V2冻结12帧的16.7779cm与复跑16.5386cm **仍是 FAIL**；其他路线成功不重写失败。
- **来源证据分层。** 既有Mesh可能是早期/不同时间/程序推断的结果；分清实测表面、被照片约束的推断表面、没有观测的未知、纯生成资产。IMU+Mesh越多，**越应**认真核对时间和坐标。
- **成本与技术成熟度分开。** `integrated_experiment` 不等于整场景质量过关，`partial` 不是完整工作流，`not_integrated` 则仅为候选。CPU/GPU算量、许可证、商业适用性及成熟外部组件的确切版本，要在用户选择具体候选后做可复现的技术决策实验，不能凭本表编造数值。

## 后续产品功能与人工决策边界

这是一版**仓库中的可运行策略选择功能**：同一catalog驱动CLI Markdown表和JSON，单元测试确保丰富输入不会只返回RGB-only，用户选择不会自动被替换，且不会在未验收时宣称已经重建。

尚未完成：浏览器端可点击的输入矩阵、输入自动识别和校验、成本/许可证的逐供应商实时比较、真实组合路线R0的端到端IMU+Mesh联合重建，以及每一次输入消融的实验曲线。它们应当以用户实际选定的候选方案为下一批功能，而不是某个GPT默认追加的工作。

**路线选择权与验收权属于用户。** 维护者仅提交数据/可逆实验；完整图像和可自由观察的空间以及独立证据仍按 #74 验收。
