## 做了什么（普通话）

真实视频上，软件先只凭RGB计算相机运动；用3张传感器实测距离确定整个路线的米制尺寸，再用48张实际测距信息组合出一个三维模型，称 **B**。完成它以后，另外做一个模型 **A**，它直接使用TUM提供的已知相机位置，但使用的**48张视频画面和测距文件，和B完全一样**。两套都拿相同12张没有参与建模的真实测距图检查，采用同一个评分程序。

原来冻结的12张中 `frame_00025` 真实相机位置缺失，所以在**首次V2运行前**预注册了0..60剔除25的新60张选择，取[4,5,9,10,14,19,24,26,29,34,35,55]共12张检查，其余48张训练。以前的B-V1不改写，不能用旧B结果与新A结果作公平对比。

## 真实结果（12张的有效传感器深度共177475像素）

| 项目 | A 真实相机位置 | B 软件估计相机位置 + 实测尺寸 |
|---|---:|---:|
| 用于建模的画面数 | 48 | 48 |
| 留出检查画面数 | 12 | 12 |
| 有模型深度可对照的像素数 | 164723 | 165555 |
| **覆盖率** | **92.8148%** | **93.2836%** |
| 没有模型覆盖的有效测距像素 | 12752 | 11920 |
| 覆盖区平均绝对误差 | **4.2684 cm** | **3.6298 cm** |
| 覆盖区平方平均误差（RMSE） | **12.8151 cm** | **10.9828 cm** |
| 覆盖区最差5%门槛（P95） | 11.4256 cm | 10.5854 cm |
| 研究筛选门槛覆盖>=80%且RMSE<=15cm | PASS | PASS |

**不要误读：** B比A这轮RMSE低，不能据此说软件的位置比实测位姿准确。时间同步、RGB/深度校准、坐标原点和网格重建范围都会影响结果；必须继续做控制变量/多场景测试才能拆分原因。这只是同一TUM传感器在未融合视角下的测距一致性，**不是激光扫描/独立表面真值**。所用密集距离来自真实传感器，**不是仅靠RGB预测出来的**。

- `ab-run-report.json`：机器原始完整过程、48张RGB与传感器Z逐项字节哈希、选择记录、真实来源与失败门禁。
